# Довідковий корпус: як додати або виправити статтю

Пояснення термінів, місць і дат та відповіді чату Хроніст будує лише з довідкового корпусу, а без джерела чесно каже, що відповіді немає. Корпус — це набір невеликих статей у `services/knowledge/data/entries`, словник варіантів написання `services/knowledge/data/synonyms.yaml` і каталог топонімів Київського повіту `services/knowledge/data/places/kyiv-uyezd.tsv`. Цей посібник для істориків і всіх, хто наповнює корпус. Технічні подробиці, оцінка якості й скрипти — в [README сервісу](../services/knowledge/README.md).

## Головне правило

Кожне твердження статті має бути в джерелі за `source_url`. Без джерела статтю не додаємо, а власні припущення в текст не вписуємо. Текст статті — переказ джерела українською, без доповнень.

## Одна стаття — один файл

Файл лежить прямо в `services/knowledge/data/entries/` (без підтек), називається латиницею за словом (наприклад `brak.md`) і складається з YAML-шапки між рядками `---` та тексту.

```yaml
---
term: брак
variants: [бракъ, шлюб]
type: term
period: XVIII–XIX
source_title: Энциклопедический словарь Брокгауза и Ефрона, статья «Брак, термин»
source_url: https://ru.wikisource.org/wiki/ЭСБЕ/Брак,_термин
source_kind: encyclopedia
licence: суспільне надбання
---
Текст статті лише з того, що є в джерелі.
```

| Поле | Що вказувати |
| --- | --- |
| `term` | слово так, як воно стоїть у документі, у написанні джерела |
| `variants` | інші написання: дореформені й українські форми; без повторів і без самого `term` (без урахування регістру) |
| `type` | `term`, `place`, `date`, `unit` або `abbr` |
| `period` | століття, які описує саме джерело, римськими цифрами: `XIX` або діапазон `XVIII–XIX` від раннього до пізнього |
| `source_title` | назва джерела й статті |
| `source_url` | адреса статті, лише `https` |
| `source_kind` | `dictionary`, `encyclopedia`, `wikidata` або `publication` |
| `licence` | `суспільне надбання` або `CC BY-SA 4.0`, залежно від джерела |
| `wikidata_id` | необов'язково, вигляду `Q123` |

Терміни не повторюються в межах одного `type` (без урахування регістру).

## Які джерела брати

1. Насамперед Энциклопедический словарь Брокгауза и Ефрона з Вікіджерел: `licence: суспільне надбання`.
2. Якщо там статті немає або потрібна сучасна назва, українська Вікіпедія: `licence: CC BY-SA 4.0`.
3. Топоніми Київського повіту беруться з каталогу `data/places/kyiv-uyezd.tsv`. Історичну належність визначає розділ Київського повіту в Похилевича (1864), Wikidata слугує для ідентифікації поселення, а сучасний район і тип звірено з КАТОТТГ.

## Словник варіантів написання

Файл `data/synonyms.yaml` допомагає пошуку знаходити давні й сучасні форми імен (`type: person`) та назв сіл і топонімів (`type: place`):

```yaml
synonyms:
  - term: Іоаннъ
    type: person
    variants: [Иоанн, Іван, Иван, Іоан]
```

Також у словник потрапляють `variants` усіх статей. Зміни до наявних записів вносьте після звірки з джерелом.

## Як внести зміну

1. Створіть гілку й додайте або виправте файл у `services/knowledge/data`.
2. Перевірте його локально з теки `services/knowledge`:

   ```sh
   uv sync --locked
   uv run ruff check
   uv run ruff format --check
   uv run pytest
   ```

   Тест `test_corpus_entries_are_valid` перевіряє шапку кожної статті й називає файл із помилкою.

3. Відкрийте PR. У описі вкажіть джерело й що саме змінено. Правила гілок і комітів — у [CONTRIBUTING.md](../CONTRIBUTING.md).
4. Після злиття підтримувач проєкту завантажує корпус на сервер скриптом `scripts/ingest.py`: повторний запуск без змін нічого не змінює, а після правки статті оновлюються лише її частини. Ключ адміністратора є лише в підтримувача, тож самостійно завантажувати корпус не потрібно.

## Як перевірити результат

Після завантаження корпусу в «Пояснити» й чаті з'являються цитати з вашої статті, з назвою джерела й ліцензією. Якість відповідей перевіряє набір з 30 запитань (`eval/qa.jsonl`: 20 із відповіддю в корпусі й 10 без неї). Якщо ваша стаття змінює відповіді, запустіть оцінку за інструкцією в [README сервісу](../services/knowledge/README.md).
