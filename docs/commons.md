# Commons: відкритий шар транскрипцій

Commons — це спільний набір прочитаних архівних аркушів, який Хроніст робить доступним для пошуку й цитування. Тут описано, що в ньому зберігається, як запис потрапляє в підтверджений стан, на яких умовах його можна використовувати й як отримати дані. Формати запитів і відповідей — у [довіднику API](api.md).

## Що зберігається

Для кожного виділеного фрагмента сервер тримає:

- хеш зображення фрагмента і його рамку на аркуші;
- шифр аркуша: архів, фонд, опис, справу й аркуш або номер зображення; за наявності, адресу переглядача на порталі;
- прочитані рядки з позначками непевності слів, текст сучасною орфографією, розкриті скорочення, сутності (люди, місця, терміни, дати) і переклад українською;
- версії тексту, історію правок рядків і підпис того, хто підтвердив.

Самі зображення сканів не зберігаються: скани належать архівам, а на сервер потрапляє лише вирізаний фрагмент для читання. Повний перелік полів запису — у розділі [«Transcription»](api.md#transcription-версія-транскрипції) довідника API.

Фрагмент без шифру читається, але до Commons не потрапляє: без шифру неможливі цитата й підтвердження.

## Стани запису

| Стан | Що означає |
| --- | --- |
| `draft` («чернетка моделі») | текст прочитала модель, людина його ще не підтвердила. У пошуку чернетки видно, лише якщо зняти «Лише підтверджені» |
| `verified` | людина перевірила текст і підтвердила його, у записі зафіксовано, хто й коли |
| `disputed` | у схемі є, але жоден маршрут API зараз цей стан не виставляє; цитата позначає таку версію як спірну, а стрічка «Нещодавно підтверджені» її не показує |

Невпевненість моделі не ховається: слова, у яких вона сумнівалась, позначені в кожному рядку (`uncertain`), а рамка рядка, оцінена за порядком, а не виміряна, має `boxSource: "estimated"`.

## Як запис стає підтвердженим

1. Модель читає виділений фрагмент: з'являється версія `draft`.
2. Користувач з акаунтом може виправити рядки. Кожна серія правок створює нову версію з наступним номером, стара не змінюється; історію правок можна прочитати окремо.
3. Підтвердити версію можуть лише користувачі, чию пошту внесено до списку підтверджувачів на сервері. Підтверджується остання версія фрагмента; панель пропонує підтвердження лише для записів із шифром.
4. Підтвердження зберігає акаунт, час і необов'язковий підпис (до 80 символів), який показують поруч із текстом. Якщо текст змінили після того, як його відкрили, підтвердження завершується конфліктом версій.

Повторне підтвердження вже підтвердженої версії нічого не змінює.

## Ліцензія й авторство

- Підтверджені транскрипції публікуються під [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.uk). Умова авторства: назвіть підтверджувача (ім'я акаунта або підпис), як це робить цитата, і дайте посилання на запис або на Хроніст.
- Скани й описи справ залишаються власністю архівів і ліцензії Commons не підпадають.
- Чернетки моделі не перевірені людиною. Ліцензію саме на чернетки в коді проєкту не зафіксовано: TODO(перевірити). Не покладайтеся на чернетку як на джерело без звірки зі сканом.
- Довідкові статті корпусу, з яких будуються пояснення, мають власні ліцензії (`суспільне надбання` або `CC BY-SA 4.0`), вказані в кожній статті; див. [corpus.md](corpus.md).

Код проєкту поширюється за [Apache-2.0](../LICENSE).

## Як отримати дані

Масового вивантаження поки немає: окремого маршруту чи дампу не існує. Дані доступні такими шляхами, усіма без входу:

| Шлях | Для чого |
| --- | --- |
| [app.khronist.org](https://app.khronist.org) | пошук за прізвищем, ім'ям чи назвою села, фільтри архіву, фонду й років |
| `GET /v1/search` | той самий пошук для програм, до 50 результатів на сторінку, курсорна пагінація |
| `GET /v1/transcriptions/recent` | стрічка нещодавно підтверджених записів |
| `GET /v1/transcriptions/:id` | один запис повністю |
| `GET /v1/transcriptions/:id/history` | історія правок рядків |
| MCP-інструмент `search_sources` | пошук з AI-асистента, див. [apps/mcp](../apps/mcp/README.md) |

Приклад: підтверджені записи за запитом «Коваленко».

```sh
curl -sS -G https://api.khronist.org/v1/search \
  --data-urlencode 'q=Коваленко' \
  --data-urlencode 'verifiedOnly=true' \
  --data-urlencode 'limit=5'
```

Запити обмежені за частотою (пошук і стрічка — 60 на хвилину з адреси), перелік лімітів — у довіднику API. Якщо вам потрібне велике вивантаження для дослідження, відкрийте issue й опишіть задачу.

## Як пошук знаходить записи

Пошук повнотекстовий. Для кожного фрагмента береться найкраща версія: підтверджена, а серед них новіша. Запит розширюється варіантами написання зі словника: давні й сучасні форми імен та назв сіл, наприклад `Іоаннъ`, `Иоанн`, `Іван`. Слова коротші за три літери, числа, римські цифри й службові слова пошук не враховує. Роки відбирають справи за їхніми датами, а не окремі записи.

## Як цитувати

Запис можна процитувати з панелі розширення або маршрутом `POST /v1/cite`. Доступні формати:

| Формат | Приклад шифру |
| --- | --- |
| `dstu`, за ДСТУ 8302:2015 | `ЦДІАК України. Ф. 127. Оп. 1078. Спр. 177. Арк. 14зв.` |
| `text`, простий текст | `ЦДІАК України, ф. 127, оп. 1078, спр. 177, арк. 14зв` |
| `markdown` | той самий рядок, посилання на портал Markdown-посиланням |

Цитата може містити текст транскрипції (`withTranscription`). Для підтвердженої версії вона називає підтверджувача й ліцензію Commons, для чернетки позначає, що текст не підтверджено.

Щоб послатися на сам проєкт, скористайтеся файлом [CITATION.cff](../CITATION.cff): GitHub показує його в меню «Cite this repository».
