# services/knowledge

Довідковий корпус, словник варіантів написання й оцінка читання та пояснень. Зона ML-команди (`docs/plan/04-ml-htr.md`, `docs/plan/05-knowledge-rag.md`).

## Запуск

```sh
cd services/knowledge
uv sync
uv run ruff check && uv run ruff format --check && uv run pytest
```

## Оцінка читання

Читає той самий код, що й прод (`createVisionReader` в `apps/api`), а рахує метрики Python:

```sh
uv run python eval/prepare_fragments.py
pnpm --filter @khronist/api read-fragments --model claude-sonnet-5-5 \
  --fragments ../../services/knowledge/eval/.cache/fragments --out <readings.jsonl>
uv run python eval/run_htr_eval.py --reference eval/gold/lines.jsonl \
  --readings <readings.jsonl> ... --out eval/results/<дата>-htr.md
```

Шляхи для `read-fragments` — абсолютні або від `apps/api`. `read-fragments` не дописує в наявний файл: для кожного прогону — новий `--out`. Протокол метрик — `docs/decisions.md`, 14 листопада. Еталонів два, обидва на тих самих фрагментах: `eval/gold/lines.jsonl` — читання історика-консультанта (CER), `eval/reference/lines.jsonl` — читання `claude-opus-5-5` (з `--reference-reader claude-opus-5-5`, розбіжність). Походження — у `README.md` теки кожного; звіт називає той еталон, який передано в `--reference`.

- `--reference-reader` — модель, яка прочитала еталон, якщо це не людина. Тоді звіт називає метрики розбіжністю з читанням цієї моделі, а не CER. Для золотого набору від людини параметр не передається.
- `run_htr_eval.py` перевіряє кожен рядок читань, падає на повторному читанні того самого фрагмента тією самою моделлю, а фрагмент еталона без читання рахує невдалим.
- «Без `[нрзб]`» — слова `[нрзб]` еталона прибираються разом зі словами читання, вирівняними з ними.
- Плутанини історичних літер рахуються посимвольним вирівнюванням еталона й читання. Якщо в слові моделі є пробіл, його позначка непевності переходить на всі частини.

## Набір запитань для «Пояснити» й чату

`eval/qa.jsonl` — 30 запитань для перевірки, що «Пояснити» й чат відповідають лише з корпусу й чесно кажуть «не знаю» (`docs/plan/05-knowledge-rag.md`, розділ 7): 20 з відповіддю в корпусі, 10 без неї. Один рядок — один JSON-об'єкт; формат перевіряє `src/khronist_knowledge/qa.py`, тест — `tests/test_qa.py`.

- `id` — `q01`…`q30`, без повторів.
- `mode` — `explain` (`POST /v1/explain`) або `chat` (`POST /v1/chat`).
- `kind` — лише для `explain`: `term`, `place` або `date`.
- `text` — для `explain` слово так, як воно стоїть у документі (до 200 символів); для `chat` — запитання дослідника українською (до 2000).
- `expected` — `answer` або `no_answer` (очікується «не знаю»).
- `relevant` — назви файлів статей у `data/entries` без `.md`, які вважаються правильним джерелом (ручна розмітка); для `no_answer` — порожній список.

Тест перевіряє, що статті з `relevant` існують, а текст запитання без відповіді не збігається з жодним терміном чи варіантом корпусу: якщо корпус дожене таке запитання, тест упаде. Запитання про дати — лише в чаті, бо календарних статей у корпусі немає, а дати в «Пояснити» API перераховує кодом. Чат — без запису аркуша.

### Оцінка «Пояснити» й чату

`eval/run_qa.py` ставить запитання одного режиму (`--mode explain` — `POST /v1/explain`, типово; `--mode chat` — `POST /v1/chat`) локальному API і рахує, скільки відповідей без джерела, скільки правильних «не знаю» і які цитати не з `relevant`. Запитання чату йде одним повідомленням користувача, без запису аркуша й без історії. Логіка підрахунку — `src/khronist_knowledge/qa_report.py`, тест — `tests/test_qa_report.py`. Звіти: `eval/results/<дата>-qa.md` для «Пояснити», `eval/results/<дата>-chat.md` для чату.

Поріг `RETRIEVAL_MIN_RANK` — змінна API, тому для кожного значення API запускається заново. Node не перекриває змінні, задані в оболонці, значеннями з `.env`, тож у PowerShell (з кореня репозиторію):

```powershell
$env:ADMIN_API_KEY='local-qa'; $env:LLM_FIXTURES='0'; $env:RETRIEVAL_MIN_RANK='0.05'; pnpm --filter @khronist/api dev
```

В іншому вікні (з `services/knowledge`) — корпус у локальний API і прогін. Адресу API задавати в оболонці: у кореневому `.env` `KHRONIST_API_URL` може вказувати на прод.

```powershell
$env:KHRONIST_API_URL='http://127.0.0.1:3000'; $env:ADMIN_API_KEY='local-qa'; $env:PYTHONIOENCODING='utf-8'
uv run python scripts/ingest.py
uv run python eval/run_qa.py ask --min-rank 0.05 --out eval/.cache/qa/0.05.jsonl
uv run python eval/run_qa.py report --runs eval/.cache/qa/0.05.jsonl ... --out eval/results/<дата>-qa.md
uv run python eval/run_qa.py ask --mode chat --min-rank 0.05 --out eval/.cache/qa/chat-0.05.jsonl
uv run python eval/run_qa.py report --mode chat --runs eval/.cache/qa/chat-0.05.jsonl --out eval/results/<дата>-chat.md
```

Корпус досить залити один раз: він лишається в локальній базі між перезапусками API.

- `--min-rank` — лише підпис прогону у звіті: скрипт не знає, з яким порогом запущено API, тож значення має збігатися з `RETRIEVAL_MIN_RANK`.
- `LLM_FIXTURES=0` обов'язковий: із заготовками відповідей модель не викликається. Один прогін — 18 викликів моделі; ліміт гостя на «Пояснити» — 10 запитів на хвилину, тож скрипт чекає за `retry-after`, і прогін триває 2–3 хвилини. Прогін чату — 12 запитань; ліміт гостя на чат — 10 на хвилину й 50 на добу з адреси, тож за добу — не більше чотирьох прогонів чату.
- Цитата належить статті, якщо назва її джерела збігається з `source_title` статті; джерело кількох статей зараховується, якщо релевантна хоч одна з них. Відповідь правильна, лише коли релевантні всі цитати. Цитата запису аркуша (`kind: record`) у чаті без запису рахується як цитата не з корпусу.
- Частки у звіті округлено вниз.

## Пакетне читання демо-фонду

`scripts/batch_recognize.py` читає зображення демо-фонду з `docs/demo-fund/pages.json` через API (`POST /v1/recognitions` з ключем API, `source: batch`), щоб публічний пошук і Commons мали прочитані аркуші до демо (`docs/plan/04-ml-htr.md`, крок 6).

- Кожне зображення — розворот метричної книги на одному друкованому бланку. Читаються дві графи бланка, де стоять імена й села: батьки (x від 0,24 до 0,52) і восприемники (x від 0,50 до 0,72); кожна від 0,25 до 0,95 висоти (друковану шапку пропущено) ділиться на 3 смуги, тобто 6 фрагментів на зображення. Межі граф узято з фрагментів оцінки читання (`eval/reference/fragments.jsonl`), вони майже однакові в усіх п'яти справах. Координати — у частках розміру зображення (`src/khronist_knowledge/batch.py`, `column_strips`). Ліміти API (7 МіБ PNG, 8000 px на сторону) перевіряються ще до надсилання.
- Шифр: `archive` — «ЦДІАК України», як надсилає розширення (а не «ЦДІАК України, м. Київ» з `pages.json`), `fond`, `opys`, `sprava`, `image`, `portal: archium`, `portalUrl` — адреса переглядача; `document` — роки справи з `years`.
- Скани зберігаються в `eval/.cache/scans` (поза git) — спільно з оцінкою читання.
- На `429` скрипт чекає `retry-after` і повторює запит; на `401` (невідомий ключ) і `503` (бюджет моделей вичерпано або читання недоступне) зупиняється. Інші помилки потрапляють у зведення, а прогін іде далі.
- Повторний запуск не читає вже прочитане: сервер упізнає фрагмент за хешем і віддає його з кешу без викликів моделі.
- Зведення (фрагменти, прочитані, з кешу, невдачі з кодами, середній час) пишеться в `--out` і тоді, коли прогін зупинено або перервано Ctrl+C.

Змінні в кореневому `.env`: `KHRONIST_API_URL` (локально `http://localhost:3000`, прод — `https://api.khronist.org`) і `KHRONIST_API_KEY` (`khr_…`; для проду видає Владислав, локальний — `pnpm --filter @khronist/api api-key:create "batch-local"`).

```sh
uv run --env-file ../../.env python scripts/batch_recognize.py --start 1 --limit 2 \
  --out eval/results/<дата>-batch.md
```

Бюджет: одне нове читання — щонайменше 3 виклики моделі (читання, нормалізація, сутності), у разі збою — до 6. Спільний `MODEL_CALLS_PER_DAY` проду — 4000 на UTC-добу, ліміт ключа — 1000 читань на добу, тож великий прогін ділиться на кілька днів через `--start` і `--limit`.

## Корпус

Одна стаття — один файл `data/entries/*.md`: YAML-шапка між рядками `---`, далі текст. Формат — `docs/plan/07-contracts.md`, розділ 5; перевіряє його `src/khronist_knowledge/corpus.py`, а тест `test_corpus_entries_are_valid` проганяє всі статті теки й перевіряє, що прочитано кожен файл.

```yaml
---
term: восприємники
variants: [восприемники, воспріемники]
type: term
period: XIX
source_title: Назва джерела
source_url: https://…
source_kind: dictionary
licence: CC BY-SA 4.0
---
Текст статті лише з того, що є в джерелі.
```

- `type`: `term`, `place`, `date`, `unit`, `abbr`.
- `variants`: непорожні, без повторів і без самого `term` (без урахування регістру).
- `period`: століття римськими цифрами (`XIX`) або діапазон двох століть через тире чи дефіс (`XVIII–XIX`), від раннього до пізнього. Інгестія передає його числами: `XVIII–XIX` → `periodFrom: 18`, `periodTo: 19`.
- `source_url`: лише `https`.
- `source_kind`: `dictionary`, `encyclopedia`, `wikidata`, `publication`.
- `licence`: `суспільне надбання`, `CC BY-SA 4.0` або `CC0 1.0`.
- `wikidata_id` необов'язковий, вигляду `Q123`.
- Терміни не повторюються в межах одного `type` (без урахування регістру).
- Статті лежать прямо в `data/entries`, без підтек; відсутня чи порожня тека — помилка. Помилка перевірки називає файл.

Кожне твердження статті має бути в джерелі за `source_url`. Без джерела статтю не додаємо.

### Правила наповнення

- Джерела: спершу Энциклопедический словарь Брокгауза и Ефрона з Вікіджерел (`licence: суспільне надбання`), де статті немає або потрібна сучасна назва — українська Вікіпедія (`licence: CC BY-SA 4.0`). Структуровані дані Wikidata позначаються `CC0 1.0`.
- `term` — слово так, як воно стоїть у документі, у написанні джерела; дореформені й українські форми — у `variants`.
- `period` — століття, які описує саме джерело, без домислів.
- Текст статті — українською, переказ джерела без доповнень.

## Інгестія

`scripts/ingest.py` надсилає корпус і словник в API через `/v1/admin/*` (`docs/plan/07-contracts.md`, розділ 2): джерела статей — у `sources`, усі чанки корпусу одним запитом — у `chunks`, `variants` статей і `data/synonyms.yaml` — у `synonyms`.

```sh
uv run python scripts/ingest.py
```

- Змінні в кореневому `.env`: `KHRONIST_API_URL` і `ADMIN_API_KEY` (локально — той самий ключ, з яким запущено API; для проду видає Владислав). Без ключа або з чужим API відповідає `401`.
- `chunks` синхронізується повним набором: чанки, яких немає в запиті, сервер видаляє, тож скрипт завжди надсилає весь корпус. Тіло — до 2 МіБ, більше скрипт не надсилає.
- `articleKey` — назва файлу статті без `.md`, `idx` — номер чанка. Стаття до 1500 символів — один чанк, довша — 2–3 з перекриттям.
- Повторний запуск без змін дає в `chunks` `inserted: 0, updated: 0, deleted: 0`; після правки статті змінюються лише її чанки. Пари `synonyms`, яких немає в запиті, не видаляються.
- `data/synonyms.yaml` — імена (`type: person`) і села та топоніми (`type: place`), формат перевіряє `src/khronist_knowledge/synonyms.py`:

```yaml
synonyms:
  - term: Іоаннъ
    type: person
    variants: [Иоанн, Іван, Иван, Іоан]
```
